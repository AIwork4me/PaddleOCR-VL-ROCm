## 2. 用户确认的不可变目标

1. 官方基线是 Linux CUDA；本项目服务 Windows AMD GPU，通过 ROCm 生态与 Windows 可用后端尽量逼近论文数据。
2. 行业认可口径保持 OmniDocBench v1.6，不升级到 v1.7。
3. Formula 必须使用官方 v1.6 `display_formula.page.CDM.ALL`；Table 必须使用 `table.page.TEDS.ALL`。
4. Text、Formula、Table 先分别保留官方统计语义并四舍五入到三位，再计算 Overall。
5. 本机 layout 模型必须通过 ONNX Runtime DirectML 在 GPU 上运行：Windows `auto` 路径必须以 `DmlExecutionProvider` 为第一 provider，并禁用静默 CPU fallback。
6. 不得用 fallback、伪造预测、错配样本或代理指标补齐评测证据。

## 3. DirectML GPU 硬合同

工作树 `.venv` 已安装 `onnxruntime-directml 1.24.4`，可用 provider 为：

```text
[DmlExecutionProvider, CPUExecutionProvider]
```

CPU provider 出现在第二位是 ORT 的正常 provider 可用列表，不代表允许 CPU 回退。合格条件是：

- `layout_provider_requested=auto`
- `layout_providers_active[0]=DmlExecutionProvider`
- `layout_fallback_disabled=true`
- DirectML 会话激活失败或 CPU-first 时 fail closed

真实 PP-DocLayoutV3 模型 smoke 已返回 12 个框。20 个精度代表案例也全部完成轻量路径捕获，均满足 DirectML-first 与 fallback disabled。权威的机器可读标量证据为：

## 5. 当前准确结论

历史 v1.6 重算结果：

| 路径 | Text Edit | Formula CDM | Table TEDS | Overall |
|---|---:|---:|---:|---:|
| 官方历史本机 | 0.034 | 96.502 | 94.239 | 95.7803 |
| 轻量历史 | 0.034 | 96.922 | 94.322 | 95.9480 |

历史正向损失页面的最大恢复池：

- Formula：最多 0.2020 Overall 点
- Table：最多 0.0618 Overall 点
- Text：最多 0.0285 Overall 点

这些是历史上限，不是已证明的生产根因或预期收益。

当前 20 个真实案例没有同边界的官方深层 trace。轻量侧可观测 layout/crop/payload/raw_vlm/final_output；官方侧只有 final scorer 可观测，更深边界均为 `unobservable`。因此 oracle 归因结果必须保持：

```text

replay calls=0
synthetic contributions=0
```

不得据此授权 prompt、crop、normalization、模型输出或 serializer 改动。
