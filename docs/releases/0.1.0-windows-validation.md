# 0.1.0 Windows Validation Record

Date: 2026-07-12

Status: partial launch-readiness evidence, not release acceptance.

## Environment

- Windows 11 build `10.0.26200`
- `AMD Radeon(TM) 8060S Graphics`
- HIP runtime `amdhip64_7.dll`
- Project base commit `afaf890`, plus the uncommitted server-output redaction
  regression fix

## Network setup attempts

An empty temporary root was used for `paddleocr-vl-rocm setup --no-start`.
The first attempt timed out connecting to `github.com`. The resumable retry
reached the release redirect but DNS resolution failed for
`release-assets.githubusercontent.com`. No checksum or installer failure was
observed. A third empty-root attempt was made after DNS recovered; the runtime
`.part` remained at zero bytes without receiving a first data block and the
stalled command was terminated. This is not a clean network-download acceptance.

## Verified-cache installation

Five existing local files were independently checked against the packaged
manifest. Every size and SHA-256 matched, including the 323,202,730-byte b9884
runtime archive, 935,769,056-byte main GGUF, 881,770,560-byte mmproj,
130,502,049-byte layout ONNX model, and 1,482-byte layout config. They were
copied into a new temporary root as a pre-verified local cache.

`paddleocr-vl-rocm setup --no-start --root <temporary-root>` then passed runtime
extraction/version verification and configuration activation. A full doctor run
reported:

- Windows, AMD GPU, HIP, config, disk, endpoint: PASS
- llama.cpp `9884 (86961efd5)`: PASS
- `Verified 5 pinned resources`: PASS
- PP-DocLayoutV3 activated with DirectML first and fallback disabled: PASS
- Port 8111: WARN because an existing intended server occupied it

## Onboarding inference

The existing-server path used the new layout installation against port 8111
and processed `examples/input/magazine.png` into 44 blocks, JSON, and Markdown.
The managed runtime was then started on isolated port `8123`; the same CLI run
again produced 44 blocks, JSON, and Markdown. The managed child process was
terminated after the run.

These smoke runs validate installation activation, doctor checks, both server
journeys, and output generation on this machine. They do not establish G0/G1/G3/G4,
benchmark quality, latency acceptance, or a clean public-network download.
